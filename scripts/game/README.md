# In-game test tools (Windows)

Drive a running Starfield from scripts to test converted content, without keyboard macros or mods.

| Script | What it does |
|---|---|
| `input.ps1` | Sends keys, text, mouse moves and clicks to the game. **Refuses to send anything unless Starfield is the foreground window** (checked before every step), so it can never type into another app. Starfield ignores `SendInput` keyboard events; set `$env:LEGACY='1'` to use `keybd_event`, which works. Steps: `key:enter`, `type:coc X`, `hold:w,1500`, `holdg:w,1500` (a hold that releases the key at once and exits 2 when the game loses the foreground), `move:dx,dy`, `click:x,y`, `wait:ms`, separated by `|`. |
| `shot.ps1`, `shot_region.ps1` | Screenshot (downscaled) / native-resolution capture of a screen region (for OCR). |
| `ocr.ps1`, `ocr_prep.py`, `parse_getpos.py` | Read console replies with the built-in Windows OCR. The console font is light grey (~150) over a dimmed game (~85): `ocr_prep` keeps bright, unsaturated pixels as black-on-white. The parser handles the OCR's quirks (labels and numbers in separate columns, `.` read as a space). |
| `readpos.ps1` | Opens the console, types a nonce (`fo4sfr<8 hex>`, echoed as an unknown command), runs `player.getpos x/y/z`, reads the replies after that echo by OCR, closes the console. Prints `x y z` (metres). Each run keeps its capture, OCR text and `read.json` (nonce, result) in its own `-Work` folder. |
| `probe_points.py`, `probe.ps1`, `probe_map.py` | **Collision mapper.** Picks floor-like pieces from an exported FO4 cell, teleports the player 1.5 m above each (`player.setpos`, god mode on), waits, reads the height. `PASS` = landed on it, `FALL` = dropped through (missing collision), `HELD` = stopped well above (e.g. the stair top). Results to CSV and a top-down map image. |
| `walk_route.py`, `walk.ps1` | **Walk check (issue #29).** Chains nearby floor pieces into short aimed steps and holds W. A rise too tall to step ends the route instead of teleporting onto it. Does not toggle god mode or close the game. Exit 0 only when every leg arrives. |
| `route_eval.py` | Offline scorer for `route_run.ps1` results: stairs (PASS / STUCK / FALL) and doors (PASS / BLOCKED / UNOPENED / …). Does not talk to the game. |
| `terrain_evidence.py` | Offline acceptance oracle for terrain probe evidence. A PASS requires pinned plan/plugin/archive hashes, plugin ground, settled frames within reach, and unique capture ids/timestamps when recorded. Numeric timestamps must keep increasing across the whole probe. Procedural or missing ground cannot pass. |
| `lease.py` | The controller lease (docs/ai/leader-core.md section 6): `claim` / `renew` / `release` / `status --require <owner>` on `<leader>\controller.json`, every change also a ledger event. Opt-in: `testqueue.py run`, `cycle.ps1` and `watchdog.ps1` consult it only with `FO4SF_LEASE_DIR` (the watchdog: `lease_dir`) set. |
| `cycle.ps1` | Close game, redeploy staging (`deploy_starfield.py`), launch via Steam, load the last save, clear the first-console-use dialog, `coc` into a cell, screenshot. With `FO4SF_LEASE_DIR` set, exit 9 before any of that unless the lease is held. |
| `testqueue.py`, `qstep.ps1` | **Queued test runner** for unattended batches (no AI calls). `plan` turns one pinned build into tests (stairs, falls, doors from both sides, movable items, travel through load doors); `run` launches the build with `cycle.ps1`, uses a dedicated save per build, turns god mode on, runs one `qstep.ps1` per test, judges PASS / FAIL / INCONCLUSIVE (a missing read or screenshot is never a PASS), checkpoints after every test (`state.json`, `results.jsonl`, per-test folders with screenshots and logs) and resumes where it stopped; `report` ranks the problems. It stops, resumable, on a STOP file, a Resource Guardian pause/stop, owner input or another window in front (or waits for an idle PC with `--wait-for-idle`). `plan-terrain` / `plan-npc` plan experiment tests from a plan.json (terrain heights; `npc_nav`: spawn a vanilla actor, make it walk to the player, sample, remove it); `plan-movable` (`movable_control`): place a vanilla or converted item in a vanilla cell, walk over it, then push it with `ApplyHavokImpulse`; `plan --impulse` adds that impulse to movable tests the walk did not move, as a diagnostic (only the walk passes a movable test). See docs/ai/test-queue.md. |
| `sky_light.py` | Time of day and weather for terrain / npc_nav tests: validates the plan fields (`time_of_day`, `time_methods`, `time_repin`, `weather`, `need_daylight`, ...), the only commands the step may type (`SetLocalTime <h>`, `SetLocalTime <h> 1`, `cgf "Game.SetLocalTime" <h>`, `fw <id>`), and `measure <png>`: the sky (mean of the top 200 rows) and the top corners of a screenshot with daylight / night / unclear and whether the time ladder can stop. The judge decides a run's light from the probe shots' corner median (else the arrival camera), says when the arrival was already as asked (commands not tested), which command made the change and what the console replied. docs/ai/test-queue.md "Time of day and weather". |
| `console_plan.py` | `console_pre` / `console_post` of terrain and npc_nav tests: the whitelist of console lines the step may type (`GetINI "<name>:<Section>"`, `SetINI "<name>:<Section>" <number>`, the time-of-day / weather lines), and the reading of each reply from the console OCR (`INISetting <name> >> <value>`, NOT FOUND, errors) for the judge and the report. docs/ai/test-queue.md "Console commands before and after the travel". |
| `parse_npc.py` | Reads one npc_nav console session (PickLastRef's id after `plr`, `GetIsID`, `GetSelf`, `getpos`, `GetDisabled`) from OCR text in either OCR layout (inline, or labels first and values after), told which values the session's commands produce; nothing before the session start (its `ClearConsole` echo, which does not clear the screen, or its first command's echo) is read; tolerant of l / 1 / \| read for I. |
| `exp_install.py` | Installs a staged experiment reversibly; `--pack` puts the whole `Data\` tree, textures included, into one General, stored `<plugin> - Main.ba2` (vanilla's layout for terrain textures), built outside the staged folder; a staged folder without a `Data\` tree (a plugin-only experiment, e.g. the converted raider) installs its plugins and no archive; `--needs` refuses to install for a runner without those features. |
| `runner_features.py` | The features this checkout's runner has (`light`, `console`, ..., `walk`); `queue.json` `needs` lists what a queue uses, and the runner (and the queue's pre-launch, `check`) refuses a queue it cannot run. docs/ai/test-queue.md "A queue needs a runner that has these features". |
| `walk_eval.py` | The `walk` kind (`testqueue.py plan-walk`; docs/terrain/walk-redrocket-sanctuary.md): `steer`, called by `qstep.ps1` once per leg, picks the next waypoint, the heading and how long to hold W (with `input.ps1`'s guarded `holdg:w,<ms>`); the judge decides a continuous walk from its reads alone (ground from the route's walk_ground.json, cell borders, the bridge, no typed teleport, no popup). The route comes from `scripts/terrain/walk_route.py`. |

Requirements: Starfield running windowed/borderless on the primary screen; the player in the cell; Python with numpy + Pillow
(`$env:FO4SF_PYTHON` can point at a venv's `python.exe`). The console achievements warning appears on the first console command
of a session and swallows input: run one harmless command first (`cycle.ps1` does).

Lessons: `con` is a reserved Windows file name (`con.png` cannot be opened); `scof` accepts a name but never wrote a file here,
hence the OCR route; walking with held keys drifts and gets stuck, teleporting with `player.setpos` is exact.
