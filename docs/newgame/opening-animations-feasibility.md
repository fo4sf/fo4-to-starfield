# Vault 111 Opening Animations & Cutscenes: Feasibility & Order

Assesses the four opening animation gaps reported from the owner's 25 Nov playtest (`#32` comment `7155932648`, Round 14 Follow-Up NEXT 1), mapping each to observed Fallout 4 archive assets and our Starfield conversion/retargeting tools.

Labels: **VERIFIED** = directly read from repository files or Fallout 4 archive headers in this checkout pass; **UNVERIFIED** = runtime Starfield behavior or unbuilt pipeline stages not yet run in the game.

---

## 1. Current Tooling Baseline

- **Prop / furniture / door object animation** (`src/fo4sf/anim_object.py`, `dotnet/AnimConsoleFour`, `dotnet/CogDoorProbe`, **VERIFIED**):
  Converts keyframed FO4 `NiControllerSequence` tracks via `CALUMI.Animation` onto `genericstategraph01.agx` (`AnimConsoleFour`), `activatorstategraph01.agx`, or `genericopenclose01.agx` / `SimpleOpenClose01.agx` (`CogDoorProbe`). Proven in game on `V111GearDoorConsole01` (4-state console) and `VltGearDoor01` (Vault 111 cog door).
- **3rd-person human actor retargeting** (`origin/claude/human-anim`: `src/fo4sf/human_retarget.py`, `docs/actors/human-animation.md`, PR `#856`, **VERIFIED offline, unmerged**):
  Retargets 95-bone FO4 `skeleton.hkx` clips onto Starfield's 97-bone 3rd-person `meshes\actors\human\characterassets\skeleton.rig` (82 clip bones) via add-on `RACE` + archetype keyword (`SFBGS003` pattern).
- **1st-person human retargeting** (`docs/actors/human-animation.md` §6, **VERIFIED as unbuilt proposal**):
  Target skeleton is Starfield's 87-bone `meshes\actors\human\_1stperson\characterassets\skeleton.rig` (76 clip bones, no legs, camera-space weapon/arm IK). Retargeter and additive writer (`*Add.hkx`) are **not implemented yet**.
- **1st-person Pip-Boy visibility limit** (`docs/ui/pipboy-arm-visibility-study.md`, **VERIFIED**):
  Vanilla `IDLE 0x000C154F` (`idleexaminewatch`) plays and logs `accepted=1`, but Starfield's outfit/spacesuit slots (`3`/`8`/`35`) hide the `Chronomark` (`0x00080D`) forearm mesh in 1st-person view until slot/sleeve occlusion is resolved.

## 3. Recommended Execution Order

1. **Catwalk gate (`V111GearRoomGate01`, Item 4 — Route A):** Highest ROI with **zero new engine prerequisites**. Build a dual-leaf swing `DOOR` / activator override (`GateL` & `GateR` rotated around their local Z pivots on `genericopenclose01.agx` / `SimpleOpenClose01.agx`), wired either to player E-activation or auto-opened with the cog door console.
2. **Pod door/thaw prop animation (`CryoPod01.nif`, Item 1 part A):** Run `anim_object.py` (`genericstategraph01.agx`) over `CryoPod01.nif` (`Thaw` / `ExitCryo` / `Open` sequences) so `MQPlayerCryopodREF` visibly opens and frost/arms retract in front of the player at pod release (works in both 1st-person and 3rd-person without actor retargeting).
3. **3rd-person cryo/console furniture clips (Item 1 part B / Item 3 fallback, gated on `#856` merge):** Once `claude/human-anim` (`#856`) lands, retarget `Actors\Character\Animations\Furniture\CryoPod\ExitToStand.hkx` onto `skeleton.rig` to replace the static `-2.5 m` pod wake-up drop (or run during a brief vanity/3rd-person sequence).
4. **1st-person retargeter + Pip-Boy sleeve fix (Items 2 & 3 primary, Item 1 full POV):** Implement `_1stperson\characterassets\skeleton.rig` support in `human_retarget.py` (`human-animation.md` §6) together with `Chronomark` (`0x00080D`) first-person sleeve visibility so `pipboyInspect.hkx`, `pipboyPlugStart.hkx`, `VaultConsole\Activate.hkx`, and `CryoPodExit\{IdleBangOnGlass,ExitToStand}.hkx` render the actual FO4 arm + Pip-Boy on pickup, console use, and pod exit.
5. **Spouse/Kellogg synced pod cutscenes (Item 1 full):** Build multi-actor cutscene orchestration only after 3rd-person humanoid NPC rigs (`#856`), `CryoPod01` prop sequences, and Vault 111 paired timing are proven in game.
