## 1. Two-Track Architecture: Track 1 (Playable FO4) vs Track 2 (Experimental Core)

Per the owner's 20 November 2026 direction, FO4SF runs on two explicit, decoupled tracks:

| Dimension | Track 1 — Fallout 4 Playable Path (`--profile player`) | Track 2 — Experimental Multi-Title Core (`--profile test`) |
|---|---|---|
| **Goal** | Provable, playable Fallout 4 story and missions in Starfield, start to finish, validated step-by-step in game. | Game-agnostic Fallout RPG/survival/warfare/living-world core engineered so `FO3`, `FNV`, `FO1`, and `FO2` sit cleanly on the same interfaces without rework. |
| **Bundle & Default State** | Ships in `--profile player` with **safe defaults** (`FO4SFRouteLoot.esm` omitted until `T1` is resolved, `MapBlockStarMap=0`, `FO4SFBridge.esm` OFF). | Ships in `--profile test`; lands on `main` as **Class B (OFF by default)** behind explicit `GLOB`/`GPOF`/INI gates. Never pulled into `--profile player` unless Track 1 needs it. |
| **Priority Order** | **(1)** New game + single working FO4 Story start, no black screen, first box draws (`T3`); **(2)** Vault 111 to surface with no crash (`T1`, `T2`, `T4`, `U1`); **(3)** Sanctuary Hills, Codsworth, walk to Concord; **(4)** Preston & Concord with dialogue choices showing (`T6`); **(5)** First missions in order (*When Freedom Calls* onward) with start, objectives, completion, save/reload; **(6)** Needed Pip-Boy pages (map, quests, inventory; wrist raise `T7` wanted but non-blocking). | Runs in parallel without waiting for Track 1 to finish, and without holding up Track 1. This round's Track 2 deliverable is **design** (this specification + `W7` Open Mode contract + Pip-Boy style hooks) rather than unrequested feature builds. |
| **Testing Lane** | Lead in-game cards (`candidate-2d-card.md` and successors) + `W6` quest state/break-it tests. | Isolated offline unit/selftest suites + `--profile test` test-cell cards (`FO4SFCoreCandidate.esm`, `FO4SF_ListTalkCell`, `FO4SF_PATestCell`, `FO4SF_RepTestCell`, `FO4SF_SquadTestCell`). |

### Architectural Invariants Keeping the Core Game-Agnostic

1. **Single Store Rule (`R13`):** Every cross-plugin or native-to-Papyrus scalar lives once in `FO4SFCoreValues.esm` (`src/fo4sf/core/core_values.json`), validated across all C#, Papyrus, and SFSE readers by `src/fo4sf/core/cross_plugin_check.py`. No per-title plugin may duplicate a shared `AVIF` or `GLOB`.
2. **Base-Plus-Data (`BASE-PLUS-DATA`):** Engine mechanics (16-state reputation math, dual-mode radiation, hardcore needs, limb `BPTD` penalties, calibre-table ammo subtypes, start-place dispatch, dialogue check formatting) live in title-neutral C#, Papyrus, and SFSE modules. Per-title specifics (starting cell, SPECIAL pool preset, perk cadence, radiation rule default, faction lists, speech-check mode, weapon/ammo maps) are **table rows**, never `if title == "FO4"` branches.
3. **Zero Vanilla Overrides by Default:** Core plugins (`FO4SFCoreValues.esm`, `FO4SFRads.esm`, `FO4SFHardcore.esm`, `FO4SFWorkshop.esm`, `FO4SFPowerArmor.esm`, `FO4SFProgression.esm`, `FO4SFListDialogue.esm`, `FO4SFCombat.esm`, `FO4SFReputation.esm`, `FO4SFCompanions.esm`) master only `Starfield.esm` (and `FO4SFCoreValues.esm` where needed) and override **zero** vanilla records. Title-specific world/cell anchors (such as `FO4Port.esm` or `FO4TerrainCore.esm` offsets) must stay in title-layer plugins or dynamic `Game.GetFormFromFile` / JSON descriptor lookups.
4. **Never Assume an NPC Lives (`W7` Forward Contract):** Every new or converted quest script in Track 1 and Track 2 must evaluate alias state via `IsDead()` / fallback globals rather than assuming essential invulnerability, so Survival/Hardcore **Open Mode** (`Section 7`) can clear essential flags cleanly later without rewriting quest controllers.

## 3. New Vegas Designer-Intended / Console-Cut Implementations

During *Fallout: New Vegas*'s 18-month development for 2005-era consoles (512 MB shared RAM on Xbox 360 / 256+256 MB split RAM on PS3), Obsidian repeatedly had to partition spaces, cap simultaneous actors, simplify NPC ammunition rules, trim eastern Legion territory reactivity, and end play at the Hoover Dam slideshow. Our 64-bit Creation Engine 2 host and Track 2 core remove those hardware ceilings. The six concrete cases below — grounded in our `FalloutNV.esm` census (`436`/`642` `QUST`, `13` `REPU`, `14` `WRLD`, `92`/`145` `AMMO`, `54`/`80` `AMEF`) and `40`-quest script audit — define what the core interfaces must support from day one:

| # | Designer-Intended FNV Feature | Original Console / Deadline Constraint (Census & Script Evidence) | How Our CE2 Core Interfaces Support the Full Version |
|---|---|---|---|
| **NV-1** | **Continuous Unsplit Vegas Strip & Freeside** | `FalloutNV.esm` splits Freeside into two gated sub-worlds (`FreesideNorth`/`FreesideEast`) and the Strip into three loading-gate zones (`TheStrip01..03`) with sparse NPC counts to stay under console memory budgets. | CE2's 64-bit cell streaming removes the 512 MB gate budget. The FNV world converter merges the Strip and Freeside exterior cells into one continuous exterior grid (removing internal partition gates and invisible walls) while preserving outer gate triggers (`TopsExteriorDoorSCRIPT` `0x129016`, Securitron credit/passport check, `VFSTheKingScript` `0x115E67`) and full intended crowd/gambler/Securitron density. |
