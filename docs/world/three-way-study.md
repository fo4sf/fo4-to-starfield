# Three-Way World Study: Fallout 4 vs. Starfield vs. FO4SF Today

Scope: read-only architectural comparison across **Fallout 4** (with all six DLC `.esm` plugins in load order), **Starfield** (`Starfield.esm` 1.16.244), and **FO4SF today** (`FO4TerrainCore.esm` + `FO4TerrainCore_Mars.esm` + active runtime/UI bridges at `cd03411a`).

All census counts are reproduced read-only via [fo4_world_census.py](../../scripts/terrain/fo4_world_census.py) and [sf_location_census.py](../../scripts/terrain/sf_location_census.py). Every unknown names the exact verification path that answers it (`record read`, `Creation Kit script sources`, `decompile`, or `in-game probe by Claude (PC)`). Per project rule `R9`, `Starfield.esm` remains an unmodified master; Starfield locations and systems are suppressed strictly by holding, hiding, or overriding from FO4SF plugins, one lever at a time.

## 1. Twelve-Concern Three-Way Comparison

### 1.1 Terrain

- **Fallout 4:** Per-cell `LAND` records carrying `VHGT` heightmaps (`33 x 33` vertices per `4,096`-unit = `58.514 m` cell, `128`-unit = `1.829 m` vertex spacing, `8`-unit = `11.4 cm` gradient step; [fo4land.py](../../src/fo4sf/fo4land.py#L6-L12), [architecture.md](../terrain/architecture.md#L164-L178)). Zero Fallout 4 `LTEX` textures and zero Fallout 4 `GRAS` records are used; FO4 trees and flora (`47` `FLOR` bases) stand as converted static/flora objects.

### 1.4 Sky and Weather

- **Fallout 4:** Each `WRLD` names a `CNAM` `CLMT` climate (`Fallout4.esm:00015F` on `Commonwealth`, `DLCCoast.esm:00AB0E` on `DLC03FarHarbor`, `DLCNukaWorld.esm:00963A` on `NukaWorld`; `scripts/terrain/fo4_world_census.py`) and `REGN` weather lists (`153` `REGN` across the 7 plugins) driving `WTHR` records under a `24 h` clock (`TimeScale = 20`).
- **Starfield:** Sky, day length, atmosphere hazards, and weather combine `STDT` (`123` stars: `PNAM` sun preset, `HNAM` `TODD`), `PNDT` (`1,765` planets: `INAM` `ATMO` atmosphere, `ENAM` rotational velocity, `FNAM` surface gravity, `TEMP` temperature, trait keywords checked by `BodyIsAtmosphereType` / `BodyIsTemperatureType`), `BIOM` `ENAM` `CLMT`, and conditioned `WTHS` weather settings ([world-planet.md](../research/framework/findings/world-planet.md#L48-L53), [world-planet.md](../research/framework/findings/world-planet.md#L110-L135)). **UNKNOWN — answer by: in-game probe by Claude (PC) and record read:** exact `PNDT` subrecord formula for `Planet.GetDayLength()` (`record read` + probe), whether `WRLD` `GNAM` (`1.0`) multiplies or replaces `PNDT` `FNAM` gravity (`in-game probe by Claude (PC)`; [world-planet.md](../research/framework/findings/world-planet.md#L228-L229)), and the visual sky appearance of `ATMO_Jemison` (`0x0000C010`) vs `ATMO_Earth` (`0x0000C9D1`) over Commonwealth terrain (`in-game probe by Claude (PC)`, owner visual judgement per `R8`).
- **Ours today:** `FO4Core_Commonwealth` has `CNAM = null` (no climate override) and sits on `MarsPlanetData` (`0x0003F59A`: `0.38 g`, `25 h` day, `-5 C`, `CO2` / `Thin` / `Cold` traits, Mars orange sky; `scripts/terrain/sf_location_census.py`, [world-planet.md](../research/framework/findings/world-planet.md#L206)). `FO4SFNewGame.esm` holds off `SQ_ENV` (`17` player hazard abilities) and tops up O2 capacity ([make_newgame.py](../../scripts/newgame/make_newgame.py#L78-L82)), leaving race hit-spell abilities, local hazards, gravity, temperature, day length, and sky unchanged.

## 3. Biome Map Lookup & Custom Home Biome (`W4`)

### 3.1 Engine Evidence: How `BSGalaxy::BiomeMapDB` Resolves `.biom` Files and Why Probe Run 1 Produced Icy Ground

Read-only inspection of `Starfield.exe` (1.16.244), `CreationKit.exe`, `Starfield.esm`, and `Starfield - PlanetData.ba2` establishes four measured facts:

1. **Lookup path is `PlanetData\BiomeMaps\<ANAM_lower>.biom`:**
   - `Starfield.exe` `.rdata` RVA `0x4AFC8A0..0x4AFC8A8` holds the extension `"biom"` and directory prefix `"PlanetData\\BiomeMaps\\"`.
   - Across all `1,437` landable `PNDT` records with `PPBD` biome entries in `Starfield.esm`, `1,437 / 1,437` match `planetdata/biomemaps/<body ANAM lower-cased>.biom` inside `Starfield - PlanetData.ba2` (`1,438` `.biom` files total), while `0` match `EDID` where `EDID != ANAM`.
2. **Exact `.biom` binary format (`magic = 0x0105`):**
   - Header: `u16 magic (0x0105)` + `u32 biome_count` + `biome_count x u32 biome_formid` (`CreationKit.exe` RVA `0x8A8B3D8`, `BSGalaxyBiomeMapDB.cpp`: `"Trying to load biome map file with invalid version"`).
   - Payload: `u32 face_count (2)` followed by `2` polar faces of `[u32 width (256), u32 height (256), u32 pixel_count (65536), 65536 x u32 biome_formid, u32 resource_count (65536), 65536 x u8 resource_index]` (`655,406` bytes total for a 1-biome planet).
3. **Why Planet Probe Run 1 (`29 Oct`) rendered icy ground outside the test cells:**
   - Probe run 1 cloned `JemisonPlanetData` (`0x0003F5A1`) whole, retaining Jemison's `5` `PPBD` biome entries (`0x0007F88A OceanLife04`, `0x000FD00D FrozenLife07`, `0x001CBD6A ForestDeciduousLifeJemison`, `0x002636BA MountainsLife03`, `0x0029434E ForestConiferousLife01`), and registered its overlay at `(0.0, 0.0)` rad.
   - Two independent mechanisms select `0x000FD00D` (`FrozenLife07`, icy ground) on that clone:
     - First, when `BSGalaxy::BiomeMapDB` cannot open a plugin planet's `.biom` stream (`CreationKit.exe` RVA `0x8A8C3D8`: `"BiomeMapDB unable to create file for %s. Using default biome."`; `Starfield.exe` RVA `0x4D60308`: `bUseFirstBiomePosition:Biomes`), the engine falls back to the planet's first non-ocean `PPBD` biome — which on `JemisonPlanetData` is `0x000FD00D` (`FrozenLife07`).
     - Second, even inside `jemison.biom` itself, both polar grid centers `(128, 128)` hold `0x000FD00D` (`FrozenLife07`).
4. **Why we give our planet a non-colliding internal body `ANAM` (`fo4sf_home_earth`) while keeping HUD `FULL` = `"Earth"` (`C9`):**
   - Vanilla `Starfield - PlanetData.ba2` already ships `planetdata/biomemaps/earth.biom` listing `0x000F1169` (`DesertSandyNoLifeEarth`) and `0x0028791F` (`FrozenNoLifeEarth`). If a plugin planet's `ANAM` equals `"Earth"` and the archive loader resolves vanilla `Starfield - PlanetData.ba2`'s `earth.biom` ahead of ours, Starfield's Earth desert/frozen biomes bleed through.
   - In `FO4SFHome.esm` ([home_planet_spec.py](../../src/fo4sf/planet/home_planet_spec.py#L49-L59) and [biom.py](../../src/fo4sf/planet/biom.py#L149-L175)), we:
     1. Author our own `"no-life, Starfield-patterned"` `BIOM` record `FO4SFHomeBiome` (`0x01000806`), assigning slots `0..6` `LNAM` to plain neutral `LDirtFootprints01` (`0x001235C2`) with `0` `GCVR` ground cover, `NAM2`/`NAM3`/`NAM4` to `PCM_BiomeDensity_None` (`0x002EDD3B`), `0` `GNAM` procedural objects, and `0` `NAM1` resources (until `WB1`–`WB3` replace its Starfield climate, sky, terrain pattern, surface tree, and ground texture references with our own);
     2. Keep the HUD display name `TESFullName_Component / FULL` on `--planet-name` (default `"Earth"`), while setting `PNDT` `BDST..BDED / ANAM` to `--body-name` (default `"fo4sf_home_earth"`, absent from all `1,438` vanilla `PlanetData.ba2` `.biom` entries; `--body-name Earth` stays available as the `b7dc7f52` control variant per `R12`), and set `PNDT` (`0x01000805`) `PPBD` to contain **only** `0x01000806` (`FO4SFHomeBiome`, `100%` weight, `0` fauna, `0` flora, `0` resources) plus `FO4TerrainCore_Home.esm` `WRLD` `BNAM = 0x01000806`;
     3. Synthesise a uniform `655,406`-byte `.biom` file (`magic 0x0105`, `1` biome `0x01000806`, `0` resource bytes) staged at both `Data/PlanetData/BiomeMaps/fo4sf_home_earth.biom` and `Data/PlanetData/BiomeMaps/fo4sfhome.esm/fo4sf_home_earth.biom`, with **both** candidate paths labelled **`TEST-STATION`** (`path_status`) until confirmed in game by Claude (PC).

## 4. Worldspace `FNAM` Flag Bits (`WL2`)

Measured across all `433` `WRLD` records in `Starfield.esm` (`scripts/terrain/sf_location_census.py`) and cross-referenced against `CreationKit.exe` RTTI/INI strings and Mutagen `Worldspace` schema definitions:

| Bit / Mask | Creation Kit / Engine Name | Meaning & Source | Count in `Starfield.esm` (`433` `WRLD`) | Set in `FO4TerrainCore_Home.esm`? |
|---|---|---|---|---|
| `0x00` (none) | Default overlay / city flags | Standard hand-built city and settlement overlay configuration (`NewAtlantis` `0x0001251B`, `CydoniaCity` `0x002CFC4A`, `akilacity` `0x0027CFA2`, `NeonCity` `0x0027CF9E`, `LC172World` `0x0002DF8C`, `TempJemisonWorld` `0x00190D2E` all carry `FNAM = 0x00`) | `431 / 433` (`99.54%`) | **Yes (`FNAM = 0x00`)** |
| Bit 0 (`0x01`) | `Allow ProcGen` (`bAllowProcGenOnOverlays:ProcGen`, `CreationKit.exe` RVA `0x87D72B0`) | Permits Planet Content Manager procedural scatter inside an overlay worldspace; set on `OverlayTraitCharredEcosystemMd02Water` (`0x002C7419`) only | `1 / 433` | **No** (would invite procedural scatter onto FO4SF terrain) |
| Bit 1 (`0x02`) | `Prevent Merge Cell Content` (`CreationKit.exe` worldspace flag string) | Suppresses merging overlay cell content into the runtime planet worldspace; unused across all `433` vanilla `WRLD`s | `0 / 433` | **No** (unproven in vanilla and risks suppressing placed cell references during planet merge) |
| Bit 2 (`0x04`) | `Allow Cell Content` (`CreationKit.exe` worldspace flag string) | Set only on `LC030World` (`0x00260A7C`); absent on all major cities and `LC172World` | `1 / 433` | **No** (not used by `LC172World` or city overlays; unproven effect) |
| Bits 3..7 (`0x08..0x80`) | Unassigned / reserved | Zero occurrences in `Starfield.esm` and no `CreationKit.exe` checkbox string | `0 / 433` | **No** |

Accordingly, `ALLOWED_WRLD_FNAM_BITS` in [home_planet_spec.py](../../src/fo4sf/planet/home_planet_spec.py) is `0x00`, and `test_planet_home.py` asserts that `FO4TerrainCore_Home.esm` sets no unproven `FNAM` bits.
