Labels: **verified** (checked, with the file or the number), **supported** (supported hypothesis), **unresolved**, **refuted**. Offline checks are not in-game acceptance.

This plan merges six read-only test-gap reviews into one ranked list of 59 items. The reviews cover gameplay, runner reliability, player experience and acceptance, NPCs and actors, world and streaming, and conversion fidelity, and propose 87 tests between them. Ranking rule: first the value to the Red Rocket -> Sanctuary -> nearby interiors slice and to the owner acceptance list (`docs/CODEX-HANDOFF.md`), then cost. A test that can find an unknown defect now ranks above one whose answer is already known ("FAIL, because the feature is not converted"). The exception is an item the acceptance list names. Duplicates across reviews are merged. Items already covered by a runner kind or a planned queue are dropped or reduced (section 6). Every console command the tests need is listed as confirmed or unresolved (section 7).

### T1. door_closed: closed doors, door frames and passable sliding doors block the player

- **Value:** high. A4 says "closed/open door collision" and A6 names the sliding doors. Vault111Cryo is the session's launch cell, so a player meets these doors first. **Cost:** medium. **Needs game:** yes. **Merged from:** the player-experience door_closed, the gameplay item (b) (closed elevator doors) and the reliability tier-2 negative control.
- **Why:** route_run resets a door with `setopenstate 0` and then always presses E, and route_eval passes a door when the player crosses after an OPEN prompt. So only the open case is measured. Placed passable doors have no closed-panel collision: 10 models and 106 refs (verified, section 1). placed_collision.py excludes passable doors by design, and routes.py plans only hinged doors (Vault111Cryo has one route door, 1A8009).
- **How:**
  - Add a new kind `door_closed`, planned from `routes_<cell>.json` door routes, every manifest item with source passable-door, and the load doors.
  - Leg A, door closed: `setopenstate 0` on hinged doors only (none on passable statics). Teleport to the route start facing the door and hold W for walk_ms with no E: route_run's `hold:w`, or #103's guarded `holdg` once merged. Then a strict readpos and a screenshot.
  - Leg B, frame: the same with the door open (`setopenstate 1`), aimed 0.6 m beside the opening edge.
  - Judge with route_eval's plane test.
  - Negative control in the same run: a staging copy with one hinged door's NIF collision stripped must FAIL GHOST.
  - Add sandbox scenarios (ghost door, solid door, frame gap) and synthetic judge tests.
- **Pass rule:**
  - PASS: in leg A no read past the door plane and the player stopped within 1.0 m of it; in leg B no read past the frame plane.
  - FAIL GHOST: crossed a closed door. FAIL FRAMEGAP: passed beside the opening. FAIL FALL.
  - INCONCLUSIVE NOREACH: stopped more than 1.5 m before the plane, or the start was not reached or not read.
  - Expected now: FAIL GHOST on the passable placements, PASS on hinged doors (supported).
- **Prerequisites:** runner feature `door_closed`; refs from formids.json; queue pinned to 2470f876, later to the #79 door build. `setopenstate 1` has never been typed by the runner (unresolved).
- **Suggested owner:** Claude.

### T3. Strict reads in every kind: OCR corpus and read-fault injection

- **Value:** high. A7 says unreadable results are inconclusive, and the A1/A5 runs are next. **Cost:** medium. **Needs game:** no. **Merged from:** the reliability "OCR read corpus" and "read-fault injection".
- **Why:** misreads were accepted as values on 2026-10-13:
  - `99.74 -2195.27 99.41` faked a 2,372 m load.
  - `-2195.27 -1.59 99.41`: a thousands group was split.
  - noon_1013 read `-2189.26 -1.66 105.15` in both attempts, giving INCONCLUSIVE MOVED twice.
  
  The strict parser is on the cave branch for door_trip only. Terrain, fall, movable, travel, route_run, the npc anchor reads and walk still use the lenient parser. A lost z digit group would give a fake FAIL HEIGHTS or NOTERRAIN. Read captures are overwritten every read, and fake_game always prints exact values (verified).
- **How:**
  1. Merge the strict parser and switch every judged kind to it.
  2. qstep passes `-Work <attempt>\reads\<n>`, so every read keeps its capture, prep image and OCR text.
  3. Write `tests/test_ocr_corpus.py`: about 50 hand-labelled real OCR texts already on disk, plus generated corruptions: a lost X, Y or Z line; a split thousands group; a dropped minus; a label/value swap; stale lines from the previous session; l/I/1 and O/0 swaps; `> >`. Run them through parse_getpos (both modes), parse_npc, console_plan.reply and incell.
  4. Add a fake_game `readpos_faults` setting (`after_n`, `mode`) with an OCR-text variant, so the real parser runs. Add sandbox scenarios for fall, movable, travel and terrain. Run each scenario clean and once per fault mode at a bounded sample of read indexes.
- **Pass rule:**
  - No parser mode used by a judged kind accepts a wrong value: a corrupted read gives unread, or the true value within 0.01.
  - The three 2026-10-13 strings stay as regressions.
  - A faulted sandbox run gives the clean verdict or INCONCLUSIVE: never a PASS/FAIL swap, never a new FAIL class, and no setpos, E, save or load typed because of a faulted read.
  - The test fails while any judged kind still calls the lenient mode.
- **Prerequisites:** merge 4afafc0's parser.
- **Suggested owner:** Claude.

### T7. Verdict policy: FAIL confirmation, flake ledger and a per-cell breaker

- **Value:** high. The FAILs feed the A3/A4 regression list, and the breaker has cost coverage. **Cost:** small for the breaker, medium for confirmation. **Needs game:** the unit part no; the confirmation pass yes. **Merged from:** the reliability "FAIL confirmation" and "breaker per (kind, cell)".

  - The breaker is keyed by (kind, cell). Judge-level classes (MISSED, HELD, LOWER, MOVED, UNOPENED) do not count; step-level classes (NOOBS, NORESULT, STOPPED, unread) do. An open breaker runs one canary test in another cell first.

- **Pass rule:**

  - The replay shows that the other 5 cells' movable tests would have run.
  - No FAIL is reported as a converter regression before it is confirmed.
