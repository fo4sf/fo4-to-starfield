## Detailed Notes & Console Workarounds

### 1. `T1` — `FO4SFRouteLoot.esm` Exterior Arrival Crash (`19–20 Nov`)
- **Observed:** With full `FO4SFRouteLoot.esm` active, Starfield crashed `2/2` times at `Starfield.exe+0x41efd6` (null pointer read at `+0x1f0`) ~`5 s` after `FO4SF_NEWGAME rt=<rt> warfare gear n=4` during exterior cell attach, and survived `2/2` times when `FO4SFRouteLoot.esm` was held off.
- **Default Gate:** `FO4SFRouteLoot.esm` is **excluded by default** from both `PLAYER_BUNDLE_PLUGINS` (`--profile player`) and `CORE_BUNDLE_PLUGINS` (`--profile test`). `make_core_bundle.py` sets `with_route_loot = False` unless `--with-route-loot` is passed explicitly, and `verify_bundle` refuses any bundle containing `FO4SFRouteLoot.esm` when `with_route_loot` is `False`. `FO4SFNewGame.esm` places a standalone Vault 111 pistol (`0x000820`) and `48` rounds (`0x000821`) directly so Story weapon pickup never depends on `FO4SFRouteLoot.esm`.

### 2. `T2` — `MapBlockStarMap` Outdoor `M`-Key Crash (`19–20 Nov`)
- **Observed:** Returning `nullptr` from a hooked `GalaxyStarMapMenu` creation callback (`MapBlockStarMap=1`) crashed at `Starfield.exe+0x2540dc6` on `19 Nov`. Switching to `MapBlockStarMap=0` (hide-only via `SuppressVanillaMapMenus()`, logging `step=map_suppress n=<k> name=GalaxyStarMapMenu sent=hide`) **passed in game on `20 Nov`**.
- **Default Gate:** Both `sfse/FO4SFPipboyMenu/FO4SFPipboyMenu.ini` and `scripts/ui/make_pipboy_stage_ini.py` default to `MapBlockStarMap=0` (`--map-block-starmap 1` is opt-in only).

### 3. `FO4SFBridge.esm` Hold (`18–21 Nov`)
- **Default Gate:** `FO4SFBridge.esm` stays **OFF by default** everywhere (`DROPPED_SLICE_ESMS` strips it when preparing clean core inputs, and `make_core_bundle.py verify` refuses any bundle listing `FO4SFBridge.esm`). Keep `FO4SFBridge.esm` held off in `<starfield-dir>` via `python scripts/game/plugin_toggle.py off --plugins FO4SFBridge.esm --starfield <starfield-dir> --why cand2d-session-bridge-off`.

### 4. `T3` & `T4` — Pre-World `FO4SF_StartRoomCell` First-Box Stall vs Direct Vault 111 Story Start (`19–21 Nov`)
- **Observed (`21 Nov`, Candidate `2d` `#833` `d62af443`):**
  - **`T4` PASSED in game:** Once past the first box, Story mode showed **one** `"Character Appearance"` box (`Quick start` first), logged `start record mode=Story ...`, `stage 10`, `looks done: Quick start`, `stage 20`, `pod settle ok=true`, `pistol filter added`, `console activator registered`, kept `status stage=20` alive every ~`6 s` for `5 min`, and `setstage 0A000800 30` logged `stage 30 by=OTHER`.
  - **`T3` FAILED in game:** In `FO4SF_StartRoomCell` (`0x00081C`), `LoadingMenu` close was never observed (`mode fade lifted by=timeout s=15`, `start ui ready released_by=timeout_delay waited_s=15.000000`), and `FO4SF_NewGameModeMsg` (`0x000806`) stayed undrawn for `50 s` until `~` Console was opened/closed and Starfield's warning dismissed.
- **Default Gate (`OFFLINE ONLY — UNPROVEN IN GAME`):** `FadeHold` now defaults to **`false`** (`DefaultFadeHold = false` in `dotnet/NewGame/Program.cs`, `DEFAULT_FADE_HOLD = False` in `scripts/newgame/make_newgame.py`, `bool Property FadeHold = false Auto Const` in `FO4SF_NewGameQuest.psc`, and `make_core_bundle.py` omits `--fade-hold` on `--profile player`). On a default player New Game, `FO4SF_NewGameQuest` skips `FO4SF_StartRoomCell` and `ModePickMsg`, moves straight into `FO4Port_Vault111Cryo` (`FO4SF_GameMode=1`, `FO4SF_SurvivalStart=0`, `FO4SF_StartChoiceDone=1`, `FadeIn("start")`, `AdvanceTo(10)`), and `IsPreworldLooksHandled()` returns `looksSetStage20` (`false` at stage `10`) so `FO4SF_NewGameLooks` presents the single `"Character Appearance"` prompt `2.0 s` after arriving in Vault 111. Pre-world setup remains opt-in via `--fade-hold` (`--no-fade-hold` retained as a no-op compatibility alias).

### 5. `U1` — Vault 111 Floor Pip-Boy (`0x00080F`) Unactivatable & Console Fallback (`21 Nov`)
- **Observed (`21 Nov`, Candidate `2d` `#833` `d62af443`):** Aiming at the Pip-Boy on the floor beside the Vault-Tec skeleton, at the skeleton body, and at the floor glint showed no activation prompt and pressing `E` logged no `pipboy pickup` line, leaving `FO4SF_PipboyAcquired` (`0x000865`) at `0` so the gear-door console (`0x000819`) refused activation.
- **Offline Root-Cause Findings & Candidate Change (`OFFLINE ONLY — UNPROVEN IN GAME`):**
  1. `dotnet/NewGame/Program.cs` previously overwrote `FO4SF_PipboyCorpsePickup` (`0x00080E`, duplicated from `Starfield.esm:0x1CCAC2`) with `FO4Port_NpcPipboyGroundTake01`'s static NIF (`COL_STATIC` physics layer, `OBND = 0`), stripping native activator crosshair raycast collision. `0x00080E` now retains `Starfield.esm:0x1CCAC2`'s proven activator model/collision (`Scale = 1.0`), matching `FO4SF_GearDoorConsole` (`0x000818`).
  2. `FO4SF_PipboyCorpsePickupRef` (`0x00080F`) was previously placed at furniture `0x075039`'s origin `(-54.456, -0.325, 0.631)` m instead of the Pip-Boy mesh world center (`local (0.01, 0.83, 0.07)` m rotated by `pbRot.Z = 3.8044 rad` -> `(-53.953, -0.986, 0.701)` m, `0.83 m` closer to the visible floor Pip-Boy).
  3. `FO4SF_NewGameQuest.psc` now logs `pipboy activator registered ref=<ref> id=<id> pos=<x> <y> <z>` alongside `console activator registered` and accepts both player (`0x14`) and `None` action refs on `PipboyCorpseRef.OnActivate`.
- **Single-Line In-Game Console Fallback (`P3`-Safe — Zero `M`, `N`, or `V` Typed Letters):**
  - When `Starfield.esm` (`00`), `BlueprintShips-Starfield.esm` (`01`), and `FO4Port.esm` (`02`) precede the bundle (`FO4SFBridge.esm` OFF), `FO4SFNewGame.esm` loads at hex slot **`0A`** in both the `21`-plugin `2d` order and the `13`-plugin Track-1 `--profile player` order (`FO4SFCoreValues.esm` = `06`, `FO4SFMission.esm` = `09`, `FO4SFNewGame.esm` = `0A`).
  - Save `<starfield-dir>\u1pick.txt` before launching so you never type `v` (`Activate`) in the interactive Console:
    ```bat
    ; u1pick.txt
    0A00080F.Activate 14
    ```
  - If `0x00080F` is still hard to aim at or unactivatable in game, open Console (`~`) and run:
    ```console
    bat u1pick
    ```
    *(Or update `u1pick.txt` to `<XX>00080F.Activate 14` if `FO4SFNewGame.esm` sits at hex slot `<XX>`; confirm `<XX>` with zero `M`, `N`, or `V` characters via `help "PipboyCorpse" 4`, which prints `<XX>00080E` / `<XX>00080F`, then check `fo4sf_newgame.0.log` for `FO4SF_NEWGAME rt=<rt> pipboy pickup equipped flag=1 worn=true`.)*
